[1:20-2:50] VALUE BEAT 2, the three building blocks CLAIM (on-screen card): "Every pipeline is built from three parts: linked services, datasets, and the pipeline itself." Spoken: "Data Factory has three building blocks, and that's most of it. First, a linked service. That's the connection: the address and the login for a place your data lives, such as a storage account or an Azure SQL database. Second, a dataset. That sits on top of a linked service and points at one specific thing inside it: one file, or one table. Third, the pipeline. That's the container for the steps you want to run, and each step is called an activity. So the shape is: a pipeline contains an activity, the activity points at datasets, and each dataset sits on a linked service that knows how to log in." [7:45-9:30] WORKED RUN, did it really run? CLAIM (on-screen card): "Test with Debug, confirm in the Monitor tab." Spoken: "Before you schedule anything, you run it once by hand. At the top of the pipeline there's a Debug button. Click it, and Data Factory runs the pipeline right now with what you've built. Watch the output panel at the bottom. You'll see the Copy activity go from queued, to in progress, to succeeded, with a green tick and a row count. That row count is your first sanity check. If it copied ten thousand rows and your file had ten thousand rows, good. If the activity turns red, click the error icon and it tells you in plain text what went wrong, usually a login that didn't take or a column type that didn't match. Then go to the Monitor tab on the left. Every run you've ever done is listed there with its status and how long it took. This is where you live once things are running, because it's how you know last night's copy went green before anyone trusts the report on top of it." [9:30-11:00] SCHEDULE + open-loop payoff CLAIM (on-screen card): "A schedule trigger runs it nightly. A watermark keeps it cheap." Spoken: "To make it repeat, you add a trigger. Click Add trigger, new, and choose Schedule. Set it to run every day at, say, 2am, pick the time zone, and save. Publish your changes, and from tonight the pipeline runs on its own on that schedule. Now the setting I promised you at the start. By default, a lot of first pipelines copy the entire source every single run. Ten thousand rows tonight, ten thousand plus tomorrow's, and it keeps growing, and you pay to move all of it every night, forever. The fix is a watermark. You store the date or the id of the last row you loaded, and in the source query you only ask for rows newer than that. So each night you copy yesterday's new rows and nothing else. On a small table you won't feel the difference. On a table with years of history, a full reload every night is the difference between paying cents and paying real money for data you already moved. Set the watermark early, before the table gets big. That's the open loop paid off. Incremental copying beats a full reload, and it's a small query change to set up." DEMO (custom animation, then screen-record): (MODALITY: animation, a clock ticks to 02:00 and the pipeline fires. A side counter contrasts "Full reload: all rows, every night" against "Incremental: new rows only".) Then cut to (screen-record, Add trigger > New > Schedule, setting recurrence to daily at 02:00 with a time-zone dropdown, Save, then the Publish all button with the change count.) PAYOFF (numbered takeaway on-screen): "Takeaway: a watermark copies only new rows, which is what keeps the bill small." RE-HOOK: "That's a complete pipeline, running nightly, staying cheap. [11:00-12:20] PAYOFF, recap + cost Spoken: "Quick recap of what you can do now. One, you know the three building blocks: a linked service is the connection, a dataset is the pointer to a file or table, and a pipeline contains the steps. Two, the factory is free to create, so there's no reason not to spin one up today. Three, your first pipeline is a single Copy activity with a source and a sink. Four, a schedule trigger runs it nightly with nobody watching. Five, a watermark copies only new rows, which is what keeps the bill small. On cost, quickly: you're billed mostly by how much the copy runs and how much compute it uses, measured in what Azure calls data integration units, plus a tiny charge per activity run. A small nightly incremental copy lands at around a few cents a day. A full reload of a big table every night is where people get a surprise on the invoice, which is exactly why the watermark matters."

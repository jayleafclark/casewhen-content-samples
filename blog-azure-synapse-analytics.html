Azure Synapse Analytics: What It Does, and Where the Bill Comes From

Quick answer. Azure Synapse Analytics is Microsoft's cloud service for large-scale data warehousing and analytics. It combines a SQL data warehouse, Apache Spark, serverless queries over your data lake, and built-in data pipelines in one workspace called Synapse Studio, so your team can store, prepare, and report on big data in one place. ---

Most teams turn on Azure Synapse Analytics, leave a dedicated SQL pool running around the clock, and get a shock at month-end when the Azure bill is three or four times what they budgeted. The service is doing exactly what they told it to do; the setting was wrong, not the tool. This walkthrough covers what Azure Synapse Analytics is, what each part costs, and how to run it without paying for compute you never use.

Azure Synapse Analytics is one workspace that pulls together four jobs that used to need four separate tools: a SQL data warehouse for heavy reporting, Apache Spark for big-data work, serverless SQL for quick questions against files in your data lake, and data pipelines to move everything around. You drive all of it from a single web app called Synapse Studio.

What does Azure Synapse Analytics do in plain English?

It bundles four tools into one place, and each one is billed separately.

The dedicated SQL pool is the classic data warehouse. You provision a fixed amount of compute power, measured in Data Warehouse Units (DWUs), and it stores your cleaned, modeled tables ready for fast reporting. This is the piece Power BI usually connects to.

The serverless SQL pool has no servers to size. You point it at files sitting in Azure Data Lake Storage Gen2 and run T-SQL straight over them. You pay per terabyte scanned, around $5 per terabyte, and nothing when you're not querying.

The Spark pool runs Apache Spark for data engineering and machine learning across very large files, in Python, Scala, or SQL.

Synapse pipelines move and transform data on a schedule, so raw files land, get cleaned, and end up in tables your reports can read.

All four read and write the same storage, so you're not copying data between products to get work done.

Why does your Synapse bill keep climbing?

Here's the part that surprises finance. A dedicated SQL pool is billed per DWU-hour from the moment you start it, whether anyone runs a query or not. A DW500c pool left on for a full month can run into thousands of dollars even if the team only touched it for two hours a day.

The mechanism is simple: provisioned compute charges for being available, not for being used. Teams spin up a pool to test something, forget it, and the charges keep adding up.

Two settings remove most of the waste. First, stop the dedicated SQL pool when it's idle. You can turn it off from the portal or on a schedule, and your storage stays put while compute billing stops. Second, move ad-hoc questions off the dedicated pool and onto the serverless pool, where you only pay for the data each query reads.

A warehouse only earns its cost if the numbers inside are right. Gartner puts the average cost of poor data quality at $12.9 million a year (Gartner), so the goal of a service like this is tables the business can trust, not just tables that load fast.

How do you query files in your data lake without moving them?

This is the trick a lot of teams miss. You do not have to load every file into a warehouse before you can report on it. The serverless SQL pool queries your ADLS data in place.

Here's the pattern that keeps those queries cheap:

  1. Store files as Parquet, not CSV. Parquet is columnar and compressed, so a query reads far fewer bytes and your per-terabyte charge drops.
  2. Partition folders by date (for example, year and month subfolders), so a query for June only scans June.
  3. Select only the columns you need. Serverless bills on data scanned, and a `SELECT *` on a wide table reads everything.
  4. Use `OPENROWSET` or an external table to point at the folder, then query it the same way you query any table.

Done this way, a report over your data lake can cost a few cents. Done with wide CSV files and `SELECT *`, the same report can scan hundreds of gigabytes and cost real money.

When should you use Synapse pipelines instead of a separate tool?

Synapse pipelines run the same engine as Microsoft Azure Data Factory. Same activities, same connectors, same mapping data flows. If you already run Azure Data Factory, everything in the Azure Data Factory docs applies inside Synapse without relearning it.

So which do you pick? Use the built-in Synapse pipelines when you want one workspace for ingestion, storage, and reporting, and one bill to read. Keep a standalone Azure Data Factory when your data movement serves many targets beyond this one warehouse, or when a separate team owns the pipelines and you want them kept apart.

Neither choice locks you in. The pipeline definitions are portable, so you can start inside Synapse and split them out later if the shape of the work changes.

Is Synapse or Microsoft Fabric the right pick in 2026?

This is the question most buyers really have, because Microsoft now points new analytics projects at Microsoft Fabric rather than Synapse.

Fabric is the newer, software-as-a-service version of the same ideas. Storage is OneLake, built in and managed for you. Compute is Fabric capacity, sold as F SKUs you can scale up or turn off. Synapse is the platform-as-a-service option: more knobs to set, more control, and more that you manage yourself.

A short assessment with someone who has built both will save you a migration you didn't need.

Frequently asked questions

Is Azure Synapse Analytics being retired? No. Microsoft keeps supporting Synapse for existing workloads, and it stays available to deploy. New investment is going into Microsoft Fabric, so plan new projects there and keep running Synapse where it already works.

What is the difference between a dedicated and a serverless SQL pool? A dedicated SQL pool is provisioned compute you size and pay for by the hour, best for modeled warehouse tables. A serverless SQL pool has nothing to size and charges per terabyte scanned, best for querying files in your data lake on demand.

Does Synapse replace Azure Data Factory? Synapse includes the same pipeline engine as Azure Data Factory, so for many teams it does the same job in one workspace. Standalone Azure Data Factory still makes sense when pipelines feed many systems or a separate team owns them.

How do I stop Synapse from costing so much? Turn off dedicated SQL pools when they're idle, store lake files as partitioned Parquet, and send ad-hoc queries to the serverless pool so you only pay for the data each query reads.

Can Power BI connect to Azure Synapse Analytics? Yes. Power BI connects to both the dedicated and serverless SQL pools, using import mode for speed or DirectQuery when you need live data straight from the warehouse.

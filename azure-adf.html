# Azure ADF: What Changed and Why It Matters

Bad data runs about 12.9 million dollars a year for the average company, and Gartner ties most of it to numbers that disagree with each other. A lot of that starts in the copy step, before anyone opens a report. Azure ADF is where that copy step lives. The service itself has not changed much. What changed is the world around it. Microsoft spent the last two years moving its analytics stack toward Fabric and OneLake, and that shifts where your new ADF pipelines should point.

What is azure adf, and what actually changed?

Azure ADF stands for Azure Data Factory. It's a managed service in Microsoft Azure with one job: move data between places and reshape it along the way. You point it at your sources, tell it where the data should land, and it runs that copy job on a schedule. No servers to run yourself.

For years, the standard pattern paired ADF with a product called Microsoft Azure Synapse Analytics. ADF moved the data, and Synapse ran the Azure Synapse Analytics data warehouse where reports and models read from. Synapse even shipped its own copy of ADF, called Synapse pipelines, so a lot of teams built their loads there instead.

Then Microsoft Fabric arrived. Microsoft folded the moving, the storage, and the modeling into one place, with OneLake as the shared storage layer underneath. Fabric passed 28,000 customers within about two years of launch, which tells you how fast teams are moving onto it. ADF still exists as its own service, and it still gets updates. The shift is that a new ADF pipeline today often lands data in a Fabric lakehouse on OneLake rather than in a stand-alone warehouse.

Why does the Synapse-to-Fabric shift matter for your reports?

You live with the output. When a number on a dashboard looks wrong, the cause often sits upstream in the way data was copied and joined, not in the report. About 67 percent of companies say they don't fully trust the data they use, in a 2025 study from Precisely and Drexel LeBow. The copy step is where a lot of that doubt starts.

What the shift changes in practice:

  • Where data lands. New builds point at OneLake, so your ADF output and your Power BI models can share one storage layer instead of copying data twice.
  • Refresh timing. Fabric can read straight from OneLake with Direct Lake, so reports see fresh data sooner after a load, without a heavy import step.
  • Cost. Synapse billed dedicated pools by the hour whether you used them or not. Fabric bills a shared capacity. Moving off an idle Synapse pool can cut a real line item.
  • Skills. The build steps carry over. If your team knows ADF, they already know most of Fabric Data Factory, since it's the same engine with a new home.

How do you build an incremental load in azure adf today?

Most loads should be incremental, not full. Copying an entire table every night wastes money and run time. This pattern works.

  1. Keep a watermark. Store the timestamp or ID of the last row ADF copied. On the next run, a lookup reads that value and the copy step grabs only rows newer than it.
  2. Parameterize the pipeline. Pass the watermark in as a parameter so one pipeline handles every table, instead of a separate copy job per table.
  3. Land it in OneLake. Write the new rows into a Fabric lakehouse so Power BI can pick them up without a second copy.
  4. Match Power BI to it. On the report side, turn on incremental refresh and set the RangeStart and RangeEnd parameters in Power Query. Power BI then refreshes only the recent date slices, and your DAX measures run over a smaller, current model.

Two more habits keep a real deployment honest. Use deployment pipelines to move a build from development to test to production, so nobody edits live pipelines by hand. And when you set row-level security on the model, test it with View As before release, so each role sees only its own rows. None of this is exotic. It's the difference between a load that runs for years and one someone rebuilds every quarter.

Where does Synapse fit now?

Synapse hasn't gone away, and plenty of estates still run on it. This is how the options line up so you can place each one.

If you're starting fresh, Fabric Data Factory into OneLake is the default now. If you have a large Synapse warehouse running well, there's no rush to move it. ADF stays the right pick when you need the widest set of connectors or you're feeding systems beyond Power BI.

When should you still reach for azure adf?

Reach for ADF when you need data moved on a schedule from many sources into one place and you want Azure to run the engine. It fits when your reports live in Power BI or Fabric and you want the copy step managed and repeatable. It's a weaker pick for real-time streaming, where you need data within seconds, and it's more than you need if all your data already sits in one database and never moves.

The plain test: if people argue about which number is right, and the argument traces back to how the data got copied and joined, ADF is part of the answer. The one new question in 2026 is where it should write, and for most teams that answer is now OneLake.

Frequently asked questions

### Is azure adf being retired?

No. Azure Data Factory is still a supported Azure service and still gets updates. What's changed is that Microsoft steers new analytics builds toward Fabric, where the same data-movement engine runs as Fabric Data Factory.

### What's the difference between ADF and Synapse pipelines?

Almost none in the engine. Synapse pipelines are ADF built into Microsoft Azure Synapse Analytics. The difference is where they live and where Microsoft is investing, which is Fabric now.

### Do I need to migrate off Synapse right away?

No. A Synapse warehouse that runs well can stay. Plan the move when you hit a cost review, a licensing change, or a new project that would rather start on OneLake.

### Does ADF work with non-Microsoft sources?

Yes. ADF ships with more than 90 connectors, including Amazon, Google, Salesforce, SAP, and standard databases. That connector range is still a reason to pick ADF over the newer Fabric pipelines.

### Where should ADF land data now?

For new work, a Fabric lakehouse in OneLake, so Power BI can read it with Direct Lake and skip a second copy. For existing setups feeding a warehouse, keep landing it where your reports already read from until you plan a move.

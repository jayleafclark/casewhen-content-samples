[2:10-3:40] VALUE BEAT 2: Woraus besteht eine Pipeline? CLAIM: SAJU: "Eine Pipeline besteht aus vier Bausteinen, mehr müssen Sie am Anfang nicht kennen." (ON-SCREEN: Claim-Karte "Verknüpfter Dienst, Dataset, Aktivität, Trigger.") PROOF: (MODALITY: screen-record.) (SCREEN-RECORD: Azure Data Factory Studio. Auf der Zeichenfläche liegt eine Pipeline mit einer Copy-Aktivität. Der Cursor umkreist nacheinander vier Stellen: den verknüpften Dienst mit dem Verbindungs-Symbol, ein Dataset, das auf eine Tabelle zeigt, eine ForEach-Schleife um die Copy-Aktivität, und rechts oben den Zeitplan-Trigger "täglich 02:00". Beim Klick auf "Debug" färben sich die Schritte grün, während die Zeilen kopiert werden.) SAJU: "Vier Bausteine, das war es fürs Erste. Der verknüpfte Dienst ist die Verbindung, also die Zugangsdaten zu Quelle und Ziel. Das Dataset sagt, welche Tabelle oder welche Datei gemeint ist. Die Aktivität ist der eigentliche Schritt, die Copy-Aktivität kopiert, eine ForEach-Schleife wiederholt sie über viele Tabellen. Und der Trigger legt fest, wann das Ganze läuft, nach Uhrzeit oder bei einem Ereignis, etwa wenn eine neue Datei ankommt. Wenn Sie diese vier Begriffe kennen, können Sie jede fremde Pipeline lesen." PAYOFF: (MODALITY: on-screen text.) (ON-SCREEN: nummerierte Karte "Merksatz 2: Verknüpfter Dienst, Dataset, Aktivität, Trigger. Damit lesen Sie jede Pipeline.") RE-HOOK: SAJU: "Eine Frage hält fast jeden auf: Wie kommt ADF an Daten, die in Ihrem eigenen Rechenzentrum liegen, hinter der Firewall?"

[3:40-5:10] VALUE BEAT 3: Wie hole ich Daten aus meinem eigenen Netz? CLAIM: SAJU: "Für Daten hinter Ihrer Firewall brauchen Sie eine selbstgehostete Integration Runtime." (ON-SCREEN: Claim-Karte "Eigenes Netz = Self-hosted Integration Runtime.") PROOF: (MODALITY: custom animation.) (ANIMATION: rechts die Cloud mit Azure Data Factory. Links ein Firmennetz hinter einer Firewall-Wand, darin eine Datenbank. In das Firmennetz setzt sich ein kleines Agenten-Symbol "Self-hosted IR". Von diesem Agenten geht ein einziger Pfeil nach außen zur Cloud, deutlich beschriftet "nur ausgehend". Über diesen Pfeil wandern die Daten heraus, die Firewall-Wand bleibt geschlossen. Unten drei Etiketten für die drei Runtime-Arten: "Azure IR, Cloud zu Cloud", "Self-hosted IR, eigenes Netz", "Azure-SSIS IR, alte SSIS-Pakete".) SAJU (über der Animation): "Die Integration Runtime ist die Rechenleistung, die die Arbeit tatsächlich ausführt. Es gibt drei Arten. Die Azure Integration Runtime läuft in der Cloud und reicht, wenn Quelle und Ziel schon in der Cloud liegen. Die selbstgehostete Runtime ist ein kleiner Agent, den Sie auf einer Maschine in Ihrem eigenen Netz installieren. Wichtig dabei: Der Agent baut die Verbindung von innen nach außen auf, Sie öffnen also keinen einzigen eingehenden Port in Ihrer Firewall. Genau das macht die IT-Sicherheit ruhig. Und die Azure-SSIS Runtime lässt Sie bestehende SSIS-Pakete unverändert in der Cloud laufen, falls Sie aus der alten Microsoft-Welt kommen." PAYOFF: (MODALITY: on-screen text.) (ON-SCREEN: nummerierte Karte "Merksatz 3: Die Integration Runtime ist die Rechenleistung. Self-hosted holt sicher aus dem eigenen Netz, ohne einen Port zu öffnen.") RE-HOOK: SAJU: "Jetzt der Teil, wegen dem Sie vielleicht überhaupt hier sind: Ist dieses ADF nicht in Fabric verschwunden?"

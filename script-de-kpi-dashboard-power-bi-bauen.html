### Kapitel 1: Kann ich ein KPI-Dashboard an einem Vormittag bauen?

[0:00-0:12] HOOK (style = 3-second-payoff-demo) Spoken (Saju, aus dem Off über die laufende Aufnahme): "Das ist ein fertiges KPI-Dashboard in Power BI. Drei Kennzahlen, ein Filter, eine Entscheidung. Ich baue es mit Ihnen von der leeren Datei aus auf." (MODALITY: screen-record) Kalter Schnitt direkt auf das fertige Management. Der Cursor klickt einen Slicer von Gesamt auf Region Nord, alle drei KPI-Kacheln aktualisieren sich sichtbar in Echtzeit. Danach ein schneller Rückwärts-Wisch auf eine komplett leere Power BI Desktop Datei. (ON-SCREEN: Karte unten links, Text: KPI-Dashboard)

[0:12-0:45] PROMISE + STAKES + OPEN LOOP (MODALITY: talking head) Saju frontal, ruhig. Spoken: "Hallo, ich bin Saju von CaseWhen. Am Ende dieser 15 Minuten haben Sie ein KPI-Dashboard, das jemand morgens wirklich öffnet, und Sie wissen, warum jede Zahl darauf steht. Kein Deko-Management mit zwanzig Kacheln, sondern drei belastbare Kennzahlen auf einem sauberen Datenmodell." Spoken (Stakes): "Das ist wichtiger, als es klingt. In Deutschland waren 149.000 IT-Stellen unbesetzt, das zeigt eine Erhebung von Bitkom aus 2023. Wenn Fachkräfte so knapp sind, darf niemand seine Zeit an ein Management verlieren, das gut aussieht und nach zwei Wochen ignoriert wird." Spoken (Open Loop): "Und ganz am Ende zeige ich Ihnen die eine Kennzahl, die auf fast jedem Management steht und trotzdem niemandem bei einer Entscheidung hilft. Behalten Sie die im Kopf." (ON-SCREEN: kurze Texteinblendung, Quelle klein: Bitkom, 2023, 149.000 offene IT-Stellen) Harter Schnitt in Kapitel 2.

### Kapitel 2: Womit fange ich an, mit den Daten oder mit dem Layout?

[0:45-2:30] VALUE BEAT 1 CLAIM: "Die meisten fangen beim Layout an. Genau deshalb bauen sie zweimal." (ON-SCREEN: Textkarte, Text: Erst die Daten, dann die Optik)

(MODALITY: screen-record) Power BI Desktop, leere Datei. Saju klickt auf Daten abrufen, wählt eine einfache Verkaufstabelle und eine kleine Datumstabelle als Quelle. Er öffnet den Power Query Editor, benennt zwei Spalten um, setzt die Datentypen richtig und lädt. Spoken: "Wir starten mit den Daten. Ich lade eine Verkaufstabelle und eine Datumstabelle. Im Power Query Editor mache ich nur drei Dinge sauber, bevor irgendetwas geladen wird: Datentypen setzen, Spalten sinnvoll benennen, offensichtlichen Müll rauswerfen. Wenn Sie das hier überspringen, holen Sie es später dreimal so teuer wieder rein." (ON-SCREEN: Cursor-Markierung auf die Datentyp-Symbole; Callout: Datentyp = Fundament)

(MODALITY: talking head) Kurzer Schnitt auf Saju, ein Satz. Spoken: "Ein Layout kann ich in fünf Minuten umbauen. Ein falsch geladenes Datenmodell zieht sich durch jede einzelne Kennzahl."

PAYOFF (nutzbar heute): "Regel eins: Formen Sie die Daten in Power Query fertig, bevor Sie die erste Kachel platzieren. Datentypen und Namen zuerst." (ON-SCREEN: nummerierte Takeaway-Karte 1) RE-HOOK: "Die Daten sind geladen. Aber sie liegen noch falsch beieinander, und das ist der Grund, warum so viele Dashboards langsam und widersprüchlich werden."

### Kapitel 3: Warum entscheidet das Datenmodell über alles andere?

[2:30-4:30] VALUE BEAT 2 CLAIM: "Ihr Management ist nur so verlässlich wie das Datenmodell darunter. Das Sternschema ist der Standard, an dem sich das entscheidet." (ON-SCREEN: Textkarte, Text: Sternschema)

(MODALITY: animation) Eigene CaseWhen-Animation des Sternschemas. In der Mitte erscheint eine Faktentabelle, benannt Verkäufe. Von den Seiten schnappen vier Dimensionstabellen heran: Datum, Produkt, Region, Kunde. Zwischen jeder Dimension und der Faktentabelle leuchtet ein Eins-zu-viele-Pfeil auf, die Filterrichtung fließt sichtbar von den Dimensionen zur Faktentabelle. Danach die Gegenüberstellung: eine einzige flache Riesentabelle, die rot aufblinkt und träge wird. Spoken: "So sieht ein Sternschema aus. In der Mitte die Faktentabelle mit den Ereignissen, drumherum die Dimensionen, mit denen Sie filtern: Datum, Produkt, Region, Kunde. Jede Beziehung ist eins zu viele, der Filter fließt von außen nach innen. Das Gegenteil ist die eine flache Tabelle, in der alles zusammengeklebt ist. Die ist langsam, sie dupliziert Werte, und jede Kennzahl darauf wird irgendwann falsch." (ON-SCREEN: Label bleibt sichtbar: Faktentabelle in der Mitte, Dimensionen außen)

(MODALITY: screen-record) Kurzer Wechsel in die Modellansicht von Power BI. Saju zieht die Datumstabelle an die Faktentabelle, die Beziehung entsteht, er zeigt auf das Eins-zu-viele-Symbol. Spoken: "In der Modellansicht ziehe ich das genauso auf. Datum an Verkäufe, eins zu viele, fertig. Kein Schnörkel."

PAYOFF (nutzbar heute): "Regel zwei: Eine Faktentabelle in der Mitte, Dimensionen außen, jede Beziehung eins zu viele. Wenn Ihr Modell so aussieht, ist die halbe Arbeit erledigt." (ON-SCREEN: nummerierte Takeaway-Karte 2) RE-HOOK: "Das Modell steht. Jetzt kommt der Teil, an dem die meisten Dashboards kippen: Was ist überhaupt ein KPI, und was ist nur eine Zahl?"

### Kapitel 4: Was macht aus einer Zahl einen echten KPI?

[4:30-6:30] VALUE BEAT 3 CLAIM: "Eine Kennzahl allein sagt nichts. Ein KPI braucht vier Bausteine, sonst ist es nur Dekoration." (ON-SCREEN: Textkarte, Text: Zahl ist nicht gleich KPI)

(MODALITY: on-screen text / kinetic) Vier Felder klappen nacheinander auf, jeweils mit einem konkreten Beispiel. Baustein eins: Ziel. Baustein zwei: Vergleichswert. Baustein drei: Definition. Baustein vier: Zuständigkeit. Jedes Feld pulst kurz beim Erscheinen, links läuft ein Beispiel mit: Umsatz 1,2 Millionen. Spoken: "Nehmen wir Umsatz 1,2 Millionen. Das ist eine Metrik, kein KPI. Erst mit vier Bausteinen wird ein KPI daraus. Erstens ein Ziel: 1,2 Millionen gegen ein Ziel von 1,4. Zweitens ein Vergleichswert: gegen den Vormonat, gegen das Vorjahr. Drittens eine klare Definition: Zählt Netto oder Brutto, ab wann gilt ein Auftrag als Umsatz. Und viertens eine Zuständigkeit: Wer ist verantwortlich, wenn die Zahl kippt." (ON-SCREEN: die vier Bausteine bleiben als kompakte Liste stehen: Ziel, Vergleich, Definition, Zuständigkeit)

(MODALITY: talking head) Saju, ein ruhiger Satz, langsameres Tempo, das ist die Kernaussage des Beats. Spoken: "Ohne die vierte, ohne Zuständigkeit, geht ein Management nach ein paar Wochen kaputt. Niemand pflegt die Definition, und dann meinen zwei Abteilungen mit Umsatz zwei verschiedene Dinge."

PAYOFF (nutzbar heute): "Regel drei: Jede Kachel bekommt Ziel, Vergleich, Definition und einen Namen dahinter. Fehlt einer, ist es keine Kennzahl fürs Management." (ON-SCREEN: nummerierte Takeaway-Karte 3) RE-HOOK: "Damit haben wir das Prinzip. Jetzt bauen wir drei echte KPIs live in DAX."

### Kapitel 5: Welche drei Kennzahlen gehören wirklich aufs Management?

[6:30-8:40] VALUE BEAT 4 CLAIM: "Drei Kennzahlen reichen. Umsatz, Zielerreichung, ein Trend. Mehr lenkt nur ab." (ON-SCREEN: Textkarte, Text: Drei KPIs, kein Deko-Management)

(MODALITY: screen-record) Power BI Desktop, Bereich Measures. Saju tippt drei Measures und man sieht sie live im Formeleditor entstehen. Erst `Umsatz = SUM(Verkäufe[Betrag])`. Dann ein `Umsatz VJ` über TREUEDATUM mit einer Zeitintelligenz-Funktion. Dann `Zielerreichung = DIVIDE([Umsatz], [Umsatzziel])`. Spoken: "Ich baue drei Measures. Umsatz als Summe. Umsatz Vorjahr mit einer Zeitintelligenz-Funktion, dafür brauche ich die Datumstabelle von vorhin, deshalb war das Modell so wichtig. Und Zielerreichung als Umsatz geteilt durch Ziel, sauber mit DIVIDE, damit eine Null im Nenner nicht das ganze Management mit einer Fehlermeldung überzieht." (ON-SCREEN: Cursor-Markierung auf DIVIDE; Callout: DIVIDE statt Schrägstrich, keine Division-durch-Null)

(MODALITY: data-viz) Kurze animierte Gegenüberstellung: links ein überladenes Management mit vierzehn Kacheln, das flimmert; rechts drei ruhige Kacheln mit Umsatz, Zielerreichung, Trendlinie. Der Blick des Zuschauers wird mit einer feinen Markierung auf die rechte Variante gezogen. Spoken: "Und ja, drei reichen. Vierzehn Kacheln sind kein Management, das sind vierzehn Ausreden, keine Entscheidung zu treffen."

PAYOFF (nutzbar heute): "Regel vier: Nutzen Sie DIVIDE für jedes Verhältnis, und halten Sie das Management bei drei Kennzahlen. Umsatz, Zielerreichung, Trend." (ON-SCREEN: nummerierte Takeaway-Karte 4) RE-HOOK: "Die Zahlen stimmen. Jetzt müssen sie so liegen, dass jemand in fünf Sekunden weiß, was zu tun ist."

### Kapitel 6: Wie baue ich ein Layout, das eine Entscheidung trägt?

[8:40-11:00] VALUE BEAT 5 CLAIM: "Ein gutes Layout beantwortet eine Frage von oben links nach unten rechts. Nicht mehr." (ON-SCREEN: Textkarte, Text: Layout trägt die Entscheidung)

(MODALITY: b-roll) Kurze reale Aufnahme: eine Hand skizziert mit Stift auf Papier ein grobes Raster, drei Kästen oben, ein breiter Kasten unten. Ruhige Werkstatt-Optik, kein Stock-Klischee. Spoken: "Bevor ich klicke, zeichne ich das in dreißig Sekunden auf Papier. Oben die drei Kennzahlen, darunter der Trend über die Zeit, links der Filter. Das Auge liest oben links zuerst, also steht dort die wichtigste Zahl."

(MODALITY: screen-record) Zurück in Power BI. Saju platziert drei Karten-Visuals oben, ein Liniendiagramm darunter, einen Datenschnitt für Region links. Er räumt auf: gleiche Abstände, dezente Titel, ein einziger Akzentton für die Zielerreichung. Er klickt den Slicer und alle Visuals reagieren. Spoken: "Drei Karten oben, Trend darunter, ein Datenschnitt für die Region links. Ich nehme genau einen Akzentton, hier für die Zielerreichung, alles andere bleibt ruhig. Und dann teste ich es: Region wechseln, und das ganze Management erzählt sofort eine andere Geschichte." (ON-SCREEN: Callout an der Karte oben links: wichtigste Zahl zuerst)

PAYOFF (nutzbar heute): "Regel fünf: Wichtigste Kennzahl oben links, ein Akzentton, ein Filter. Wenn das Management in fünf Sekunden eine Frage beantwortet, ist es fertig." (ON-SCREEN: nummerierte Takeaway-Karte 5) RE-HOOK: "Auf Ihrem Bildschirm ist es perfekt. Der eigentliche Test kommt jetzt: Sie teilen es, und plötzlich sehen zwei Leute unterschiedliche Zahlen."

### Kapitel 7: Wie teile ich das Management, ohne dass die Zahlen auseinanderlaufen?

[11:00-13:15] VALUE BEAT 6 CLAIM: "Beim Teilen zerfallen die meisten Dashboards. Ein zertifiziertes Modell und Berechtigungen pro Nutzer halten sie zusammen." (ON-SCREEN: Textkarte, Text: Teilen ohne Auseinanderlaufen)

(MODALITY: animation) Eigene CaseWhen-Animation. Erst eine Datei, die sich in fünf Kopien aufteilt, jede mit einer leicht anderen Umsatzzahl, rot markiert. Dann die saubere Variante: ein zentrales Datenmodell in der Mitte, mit einem grünen Zertifiziert-Siegel, aus dem mehrere Berichte gespeist werden, alle zeigen dieselbe Zahl. Danach die Berechtigungen pro Nutzer: derselbe Bericht, zwei Personen, bei der einen filtern sich Zeilen sichtbar heraus, weil sie nur ihre Region sehen darf. Spoken: "Das hier ist der Moment, an dem Vertrauen entsteht oder verschwindet. Wenn jeder seine eigene Kopie zieht, haben Sie bald fünf Umsatzzahlen. Die saubere Lösung: ein zentrales, zertifiziertes Datenmodell im Power BI Service, aus dem alle Berichte trinken. Eine Definition, eine Zahl. Und wenn nicht jeder alles sehen darf, kommen Berechtigungen pro Nutzer dazu, in Power BI heißt das Row-Level Security. Derselbe Bericht, aber der Kollege aus Nord sieht nur Nord." (ON-SCREEN: Label bleibt: zertifiziertes Datenmodell, Berechtigung pro Nutzer)

(MODALITY: talking head) Saju frontal, hier die Auflösung des offenen Endes. Spoken: "Und da ist auch die Kennzahl, die ich am Anfang versprochen habe. Die Zahl, die auf fast jedem Management steht und nichts entscheidet, ist der reine Gesamtwert ohne Vergleich. Umsatz gesamt, riesige Ziffer, kein Ziel, kein Vorjahr. Sie sieht wichtig aus und sagt Ihnen nichts. Ersetzen Sie sie durch Zielerreichung, dann trägt die Kachel eine Entscheidung statt nur eine Ziffer."

PAYOFF (nutzbar heute): "Regel sechs: Teilen Sie ein zertifiziertes Modell, nicht fünf Kopien, und regeln Sie den Zugriff pro Nutzer. So bleibt die eine Zahl die eine Zahl." (ON-SCREEN: nummerierte Takeaway-Karte 6) RE-HOOK: "Das war der ganze Weg. Fassen wir zusammen, was Sie mitnehmen."

### Kapitel 8: Was nehme ich mit, und wie geht es weiter?

[13:15-14:15] PAYOFF (Rekapitulation, offenes Ende bezahlt) (MODALITY: on-screen text / kinetic) Die sechs Regeln laufen als saubere Liste ein, eine nach der anderen. Spoken: "Sechs Regeln, und Sie haben ein Management, dem Ihr Team glaubt. Eins: Daten in Power Query fertig formen, bevor Sie eine Kachel setzen. Zwei: Sternschema, Faktentabelle in der Mitte. Drei: jede Kennzahl braucht Ziel, Vergleich, Definition und Zuständigkeit. Vier: drei KPIs, DIVIDE für Verhältnisse. Fünf: wichtigste Zahl oben links, ein Akzentton, ein Filter. Sechs: ein zertifiziertes Modell teilen, Zugriff pro Nutzer regeln." (ON-SCREEN: die sechs Regeln als vollständige Liste, gut lesbar) Spoken: "Und die versprochene Falle kennen Sie jetzt auch: die große Gesamtzahl ohne Vergleich raus, Zielerreichung rein."

[14:15-15:00] SOFT CTA (MODALITY: talking head) Saju, ruhig, kein Druck. Spoken (Lead-Magnet): "Damit Sie das an Ihrem eigenen Modell prüfen können, habe ich unten die 20-Punkte-Checkliste für Ihr Power BI Datenmodell verlinkt. Da steht Punkt für Punkt drin, woran Sie erkennen, ob Ihr Modell ein KPI-Management wirklich trägt. Die Beispiel-Datei aus diesem Video liegt gleich daneben." Spoken (We should talk): "Und wenn Sie das an echten Berichten durchziehen und die Zahlen bei Ihnen einfach nicht zusammenpassen wollen, dann ist genau das unsere Arbeit bei CaseWhen. Buchen Sie einen Datenmodell-Check, damit Menschen und auch Copilot am Ende dieselbe, richtige Zahl bekommen. Nur ein Gespräch, kein Verkauf. Der Link steht in der Beschreibung." Spoken (Watch-next): "Wenn Sie beim Sternschema tiefer einsteigen wollen, das Video dazu verlinke ich hier. Bis dahin." (ON-SCREEN: zwei Link-Karten, Checkliste und Gespräch buchen; feiner Verweis auf das nächste Video)

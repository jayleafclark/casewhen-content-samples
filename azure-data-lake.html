Azure Data Lake: What Changed and Why It Matters

Quick answer

An Azure data lake is a single, cheap storage layer in Azure where you keep raw and prepared data of any shape, then run analytics and Power BI on top of it. The shift worth knowing: it now runs on ADLS Gen2 and OneLake, so one copy of your data can feed every tool without a fresh export each time.

If your Power BI reports read from a dozen manual exports and still show different totals, an Azure data lake is usually the first thing a data team sets up to stop the mess. It is one storage account that keeps every raw file and every cleaned table in one place, so every report reads from the same copy. That sounds dull. It is also the difference between a number you can defend in a board meeting and one you have to apologize for later.

Below is what changed, why it matters for the totals you publish, and how the pieces (ADLS, OneLake, and Microsoft Data Factory) fit together.

What is an Azure data lake?

An Azure data lake is a storage account in Azure built for analytics. You drop files into it in any format: CSV, JSON, Parquet, images, logs, whatever the source sends. Storage is cheap, so you keep the raw data and the cleaned data side by side. Nothing gets thrown away, and you never have to guess which export was the good one.

Two things make it a lake and not just a folder of files. First, it separates storage from compute, so you pay for the disk space and the processing on their own meters and scale each one on its own. Second, it uses a hierarchical namespace, which means real folders and file-level security instead of a flat container. That is what ADLS Gen2 added, and it is why your ADLS data can carry proper access rules for each team.

What changed, and why does it matter now?

For years an Azure data lake was a staging area. You landed data in it, cleaned it, then loaded it into a separate warehouse for reporting. In 2023 Microsoft launched OneLake as part of Fabric, and that setup changed.

OneLake is one lake for the whole tenant. Every Fabric workspace writes to it, and Power BI can read straight from it in a mode called Direct Lake, with no import and no scheduled copy. Your ADLS Gen2 accounts link in through shortcuts, so data you already have shows up in OneLake without moving a byte.

Why does this matter for the numbers you report? Because most reporting problems start with copies. Every export, every extra load, every stale refresh is another chance for two reports to disagree. Gartner puts the average cost of poor data quality at $12.9 million per year. Precisely found that 67 percent of organizations do not fully trust the data they use to make decisions. One governed copy in the lake removes a whole class of those errors before they ever reach a dashboard.

Gen1 is gone. Microsoft retired it on 29 February 2024, so any pipeline still pointing at it needs to move. Gen2 is the current standard for a raw Azure data lake, and it sits on top of Blob storage with a hierarchical namespace switched on. OneLake does not replace Gen2. It sits over it. You can keep your ADLS Gen2 accounts and surface them in OneLake through a shortcut, which means one folder can be read by Fabric, Databricks, and Power BI at once.

Where does Microsoft Data Factory fit into all of this?

Storage on its own does not move data. Microsoft Data Factory is the service that copies data from your sources into the lake and runs the steps that clean it. You will see it written both ways, Microsoft Data Factory and Data Factory Microsoft, and inside Fabric it shows up as Data Factory pipelines and dataflows. Same idea, one home.

A normal setup looks like this. Data Factory pulls from your SQL databases, SaaS apps, and files on a schedule. It lands the raw data in the lake, runs a cleaning step, and writes tidy tables back. Power BI reads those tables. If a source changes shape, you fix one pipeline in Data Factory instead of ten reports.

Do you still need a warehouse if you have a lake?

Sometimes yes. A lake is great for cheap storage, big files, and data science. A warehouse still wins for fast, concurrent SQL queries and strict table structure. Many teams run both and call it a lakehouse: lake storage underneath, warehouse-style tables and governance on top. Fabric packages that pattern directly, with a Lakehouse item and a Warehouse item that both write to OneLake.

The practical rule: if your questions are known and your users need sub-second dashboards, keep a modeled warehouse or a semantic model in front. If your data is large, messy, or changing shape, land it in the lake first and shape it there. Most real setups need both, and the lake is the shared storage they read from.

How do you set one up without regret?

Start with the model, not the storage. Decide the tables and the numbers you need to report, then design the lake folders around them: raw, cleaned, and curated. Name those three zones the same way in every workspace, so a new engineer can find the trusted layer in seconds. Put access rules and row-level security on the ADLS data from day one, because retrofitting them later is painful. Pick one tool to load data, usually Microsoft Data Factory, and route everything through it so you have one place to look when a number moves. Store your cleaned tables as Parquet or Delta, since that is the format Direct Lake reads fastest.

Frequently asked questions

Is an Azure data lake the same as OneLake? No. OneLake is the single lake built into Microsoft Fabric, and it stores its files as ADLS Gen2 underneath. A classic Azure data lake is one you set up and manage yourself. You can connect your own ADLS accounts to OneLake with a shortcut.

What replaced Azure Data Lake Storage Gen1? ADLS Gen2 replaced it. Microsoft retired Gen1 on 29 February 2024, so any workload still on Gen1 needs to move to Gen2 or OneLake.

Do I need Microsoft Data Factory to use a data lake? You need something to move and shape data, and Microsoft Data Factory is the standard choice in Azure. It is built into Fabric as pipelines and dataflows, so most teams use it there.

Can Power BI read from a data lake without importing the data? Yes, with Direct Lake mode in Fabric, Power BI reads Parquet files straight from OneLake, so there is no import step and nothing to refresh on a timer. A classic ADLS Gen2 lake still uses import or DirectQuery.

Lake, warehouse, or lakehouse, which do I pick? Pick a lakehouse if you want one home for both raw files and modeled tables. Pick a plain warehouse if all you need is fast SQL on clean, structured data. Most teams end up with a lake underneath and warehouse-style tables on top.

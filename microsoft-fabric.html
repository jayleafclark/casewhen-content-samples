Microsoft Fabric einfach erklärt

Quick answer.

Microsoft Fabric ist Microsofts Datenplattform, die sieben Werkzeuge auf einer einzigen Datenablage namens OneLake zusammenführt: Data Factory, Data Engineering, Warehouse, Real-Time Intelligence, Data Science, Databases und Power BI. Sie kaufen eine Capacity, alle Werkzeuge teilen sie sich, und die Daten liegen nur einmal.

Microsoft Fabric ist die Antwort auf ein teures Problem: Ihre Umsatzzahl liegt in vier Systemen und in jedem steht etwas anderes. Jeden Monat suchen im deutschsprachigen Raum rund 5.400 Menschen nach dem Begriff, und die meisten wollen dasselbe wissen, bevor sie es einschalten: Was ist das, was kostet es, und was muss ich als Person tun, die die Berichte tatsächlich baut. Genau das steht hier.

Erst kurz, warum das für Ihr Geschäft zählt. Schlechte Datenqualität kostet Firmen im Schnitt 12,9 Millionen Dollar pro Jahr (Gartner). 94 Prozent der Tabellen, mit denen Entscheidungen getroffen werden, enthalten Fehler (Poon et al., 2024). Und 67 Prozent der Firmen vertrauen den Zahlen nicht, mit denen sie steuern (Precisely und Drexel LeBow, 2025). Der rote Faden hinter allen drei Zahlen ist derselbe: dieselbe Kennzahl liegt an zu vielen Orten. Fabric setzt genau da an.

Was ist Microsoft Fabric, in einfachen Worten erklärt?

Bisher hatte ein Datenteam einen Werkzeugkasten aus getrennten Diensten: einen für Pipelines, einen fürs Warehouse, einen für Reports, oft noch einen Data Lake in Azure daneben. Jeder Dienst mit eigener Rechnung, eigener Rechteverwaltung und einer eigenen Kopie der Daten.

Microsoft Fabric legt diese Werkzeuge auf einen gemeinsamen Boden. Der Boden heißt OneLake, eine einzige Datenablage pro Firma im offenen Delta-Parquet-Format. Die Umsatztabelle liegt physisch einmal. Wer sie in einem anderen Arbeitsbereich braucht, legt eine Verknüpfung an, eine Shortcut, statt eine zweite Kopie zu ziehen. Darüber sitzen die sieben Workloads, und Power BI ist einer davon, die Sicht-Schicht auf alles, was die anderen sechs vorbereitet haben.

Der praktische Gewinn für Sie als Erbauer: Sie modellieren einmal sauber, und alle lesen dieselbe Zahl. Fabric hat innerhalb der ersten zwei Jahre über 28.000 Kunden erreicht (Microsoft, Ignite 2025). Viele davon haben es eingeschaltet, bevor sie diesen einen Punkt verstanden hatten, und dann für Rechenleistung gezahlt, die niemand nutzt.

Was ändert sich bei Power BI vs Fabric?

Die häufigste Frage ist Power BI vs Fabric, und die Antwort ist keine Entweder-oder-Frage. Power BI ist Teil von Fabric. Der Unterschied liegt darin, was drumherum passiert. Power BI allein ist Ihr Berichtswerkzeug. Fabric ist die ganze Plattform darunter, inklusive der Pipelines und des Warehouse, auf denen die Berichte stehen.

Hier stehen beide nebeneinander.

Die entscheidende Zeile ist Azure Data Engineering. Wer heute Rohdaten in Azure aufbereitet, bevor Power BI sie sieht, betreibt zwei getrennte Welten. In Fabric sitzt diese Aufbereitung im selben Produkt, auf denselben Tabellen, mit denselben Rechten. Das spart die Übergaben zwischen den Systemen, an denen Zahlen sonst auseinanderlaufen.

Wie richten Sie inkrementelle Aktualisierung mit RangeStart und RangeEnd ein?

Sobald eine Faktentabelle groß wird, dürfen Sie nicht jede Nacht alles neu laden. Die inkrementelle Aktualisierung lädt nur das, was sich geändert hat. So setzen Sie sie auf, Schritt für Schritt:

  1. Zwei Parameter anlegen. In Power Query erstellen Sie zwei Parameter vom Typ Datum/Uhrzeit. Sie müssen exakt RangeStart und RangeEnd heißen, sonst erkennt Power BI sie nicht.
  2. Die Datumsspalte filtern. Filtern Sie die Datumsspalte Ihrer Faktentabelle so, dass sie größer oder gleich RangeStart und kleiner als RangeEnd ist. Das ist der Ausschnitt, den eine einzelne Partition abdeckt.
  3. Die Richtlinie definieren. Klicken Sie im Modell mit der rechten Maustaste auf die Tabelle, wählen Sie die inkrementelle Aktualisierung, und legen Sie fest: Daten der letzten fünf Jahre archivieren, nur die letzten zehn Tage neu laden.
  4. Veröffentlichen und die erste Aktualisierung laufen lassen. Der erste Durchlauf zerlegt die Tabelle in Partitionen. Jede folgende Aktualisierung fasst nur noch die letzten zehn Tage an. Aus einer Stunde Ladezeit werden ein paar Minuten.

Ein Fallstrick aus der Praxis: Wenn Ihre Quelle die Filter nicht bis zur Datenbank durchreicht, das sogenannte Query Folding, lädt Fabric im Hintergrund doch alles und verwirft es erst danach. Prüfen Sie in Power Query, ob die Schritte gefaltet werden, bevor Sie sich auf die Ersparnis verlassen.

Wie prüfen Sie Berechtigungen mit View As und DAX?

Wenn der Vertrieb Nord nur seine eigenen Zahlen sehen darf und der Vorstand alles, brauchen Sie Sicherheit auf Zeilenebene, im Modell Row-Level Security genannt. Das läuft über eine Rolle mit einem DAX-Filter.

In Power BI Desktop öffnen Sie Rollen verwalten, legen eine Rolle Nord an und schreiben einen Filterausdruck auf die Regionstabelle, etwa `[Region] = "Nord"`. Für Filter je angemeldetem Nutzer nehmen Sie `USERPRINCIPALNAME()`, dann bindet die Rolle die E-Mail-Adresse an die erlaubten Zeilen.

Und jetzt der Schritt, den die meisten überspringen: testen Sie es, bevor es live geht. Über View As, im Menü Als Rollen anzeigen, wählen Sie die Rolle Nord und sehen den Bericht mit deren Augen. Zeigt er mehr als die Region Nord, ist der Filter offen, und Sie haben es gefunden, bevor es ein Kunde findet. Eine falsch gesetzte Zeile hier ist der Unterschied zwischen einem sauberen Bericht und einem Datenleck.

Wie bringen Sie Änderungen mit Deployment Pipelines sauber in Produktion?

Wer direkt im Produktiv-Arbeitsbereich baut, überschreibt früher oder später einen Bericht, den gerade jemand ansieht. Deployment Pipelines geben Ihnen drei getrennte Stufen: Entwicklung, Test und Produktion.

Sie arbeiten in Entwicklung. Ein Klick auf Bereitstellen hebt den Stand nach Test, wo Fachbereich und Datenprüfung ihn ansehen. Passt er, hebt der nächste Klick ihn nach Produktion. Über Bereitstellungsregeln tauscht Fabric dabei die Datenquelle je Stufe aus, damit Test auf die Testdatenbank zeigt und Produktion auf die echte. Sie fassen die produktiven Zahlen erst an, wenn der Stand geprüft ist. Genau diese Trennung fehlt in den meisten Teams, die uns rufen.

Wann lohnt sich Microsoft Fabric Beratung, und wann nicht?

Ehrliche Antwort zuerst: nicht jeder braucht Fabric. Wenn Ihr ganzer Bedarf ein paar Power-BI-Berichte für ein kleines Team sind, zahlt Fabric vor allem Capacity, die Sie nie ausschöpfen. Dann reicht Power BI Pro für rund 14 Dollar pro Person und Monat.

Fabric lohnt sich, wenn mehrere Dinge zusammenkommen: verstreute Datenquellen, mehrere Teams, die dieselbe Zahl brauchen, laufende Datenströme, oder ein Premium-Vertrag, der ohnehin auf Fabric umzieht. Eine Microsoft Fabric Beratung setzt genau hier an, und der Wert steckt weniger im Klick auf Einschalten als in der Frage davor: welche Capacity-Stufe passt zu Ihrer echten Spitzenlast, welche Berichte ziehen am meisten, und trägt sich das überhaupt.

Wenn Sie das für Ihr Team prüfen wollen, laden Sie unten die kostenlose Fabric-Readiness-Checkliste herunter. Sie geht die Punkte aus diesem Text durch: Ablage, Capacity, die richtige Stufe und die Frage nach dem Nutzen. Und wenn Sie danach noch unsicher sind, ob Sie Fabric aktivieren oder bei Power BI bleiben, buchen Sie bei CaseWhen einen Fabric-Readiness- und Capacity-Check. Kein Verkaufsgespräch, einfach die Rechnung auf Ihrem Aufbau gemacht.

Häufige Fragen

Ist Microsoft Fabric dasselbe wie Power BI? Nein. Power BI ist einer der sieben Workloads in Fabric und übernimmt die Berichte. Fabric ist die Plattform darunter, mit Pipelines, Warehouse und der gemeinsamen Ablage OneLake. Wer heute Power BI nutzt, nutzt bereits ein Stück Fabric.

Was kostet Microsoft Fabric? Sie kaufen eine Capacity, gemessen in Capacity Units. Die kleinste Stufe F2 liegt bei rund 263 Dollar im Monat, ab Stufe F64 dürfen alle Betrachter die Berichte ohne eigene Pro-Lizenz öffnen. Darunter braucht jeder Betrachter weiterhin eine Pro-Lizenz.

Brauche ich Azure, um Fabric zu nutzen? Nein, ein getrenntes Azure-Setup ist nicht nötig. Fabric bringt die Bausteine für Azure Data Engineering, also Data Factory und Spark, direkt mit. Ein bestehender Azure Data Lake lässt sich per Shortcut in OneLake einbinden, ohne die Daten zu kopieren.

Ersetzt Fabric mein Data Warehouse? Für viele Teams ja. Der Warehouse-Workload in Fabric ist ein vollständiges SQL-Warehouse auf OneLake. Ob sich die Migration lohnt, hängt an Datenmenge, laufenden Verträgen und dem Aufwand, bestehende Pipelines umzuhängen.

Wie schnell kann ich Fabric einschalten? Der Schalter ist in Minuten umgelegt. Der ehrliche Zeitrahmen bis zu vertrauenswürdigen Berichten liegt eher bei Wochen, weil Modellierung, inkrementelle Aktualisierung und Berechtigungen sitzen müssen, bevor jemand den Zahlen traut.

Was ist Direct Lake? Direct Lake ist der Modus, in dem Power BI die Delta-Tabellen in OneLake direkt liest, ohne Import und ohne langsame Live-Abfrage. Sie bekommen die Frische einer Live-Verbindung mit dem Tempo eines importierten Modells.

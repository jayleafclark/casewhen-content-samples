Governance & trustDESajurow-level security aufsetzenOpen & review →
Row-Level Security ist eine einzige Regel auf dem Datenmodell.
Viele stellen sich das als lange Rechteliste pro Bericht vor. In Wirklichkeit ist es eine Regel an einer Stelle, die festlegt, welche Zeilen eine Person sehen darf. Sie definieren eine Rolle und geben ihr einen Filter. Ein Beispiel: Region gleich der Region des angemeldeten Nutzers. Diese eine Regel wirkt dann in jedem Bericht, der auf dem Modell aufsetzt. Row-Level Security aufsetzen heißt genau das: eine Regel, dynamisch gehalten und vorher getestet. Statt für jede Region eine eigene Rolle zu pflegen, verknüpfen Sie den angemeldeten Nutzer über eine Tabelle mit seinen erlaubten Zeilen. So wächst die Regel nicht mit jeder neuen Person mit. Kommt ein Mitarbeiter dazu, ergänzen Sie eine Zeile in der Tabelle, nicht eine Rolle im Bericht. Und testen Sie die Regel, bevor sie live geht. Power BI kann einen Bericht in der Rolle eines bestimmten Nutzers anzeigen, sodass Sie sehen, was diese Person wirklich sieht. Wer es so aufsetzt, verhindert den teuersten Fall: dass jemand Gehalts- oder Kundendaten sieht, die nicht für ihn bestimmt sind, und ein Prüfer es später im Zugriffsprotokoll findet.

Data Factory: What It Actually Does (Plain English)

Quick answer

A data factory is Azure's managed service for moving and transforming data on a schedule. Azure Data Factory copies data out of your sources, lands it in storage such as Azure Data Lake Gen2, reshapes it, and loads it into a Synapse data warehouse. Your reports then run on one clean, current copy instead of manual exports.

Poor data quality costs the average organization $12.9M a year, according to Gartner. A lot of that bill traces back to one habit: numbers copied by hand between tools, spreadsheets that drift out of date, and a Monday report that no longer matches the source. A data factory is how you stop paying that tax. It moves the data for you, on a schedule, the same way every run, so finance and the sales dashboard read from the same current numbers instead of five stale exports.

Most of the time, data factory means one specific thing: Azure Data Factory ADF, Microsoft's cloud service for building data pipelines. This is the plain-English version of what it does, how it works, and when you need it.

Why does the data factory matter to the business?

Nobody upstairs cares about pipelines. They care that the revenue number in the board pack matches what's in the CRM, and that it's right on the day of the meeting, not two days late.

That gap is where a data factory earns its place. When the numbers move by hand, someone forgets a step, a filter changes, and the report goes wrong without anyone noticing. Gartner puts the cost of that at $12.9M a year for the average company, and a peer-reviewed study by Poon and colleagues found 94% of business spreadsheets used in decisions contain errors. A data factory removes the hand-copying. The same steps run every night and get logged, so when a number looks off you can see exactly which run produced it.

What does a data factory actually do?

ADF has a handful of building blocks you work with directly:

  • Linked services: the connection details for a source or destination, such as a SQL database, a blob container, or a REST API.
  • Datasets: a pointer to the specific table or file you're reading from or writing to.
  • Activities: the unit of work. The Copy activity moves data. A Mapping Data Flow transforms it without you writing code.
  • Pipelines: an ordered group of activities you run together.
  • Triggers: what starts a pipeline, whether that's a schedule, a tumbling window, or an event such as a new file landing in storage.

Put those together and you get a repeatable job: pull from here, clean it, drop it there, on a timer. That's the whole idea. Everything else is detail.

How does Azure Data Factory move data step by step?

Here's what a first real pipeline looks like end to end:

  1. Create a linked service to your source, say a production SQL database, and one to your storage account.
  2. Define a dataset for the table you want and a dataset for where it lands.
  3. A Copy activity reads the source and writes the raw data into Azure Data Lake Gen2.
  4. A Mapping Data Flow cleans and reshapes it: fix types, drop test rows, join reference tables.
  5. A second Copy activity loads the finished data into your Synapse data warehouse.
  6. A schedule trigger runs the whole pipeline at 5am, so the morning reports are already current when people log in.

For large tables you don't reload everything every night. You store the last-loaded timestamp, called a watermark, and the next run only pulls rows newer than that. This is incremental loading, and it's the difference between a five-minute nightly job and a two-hour one.

One more piece worth knowing: the integration runtime is the compute that does the actual moving. The default Azure one needs no setup. A self-hosted one runs on a machine inside your network so the pipeline can reach data behind your firewall.

Teams also version pipelines through Git. You connect the factory to a repository, build in a feature branch, and publish to production once it's reviewed. That turns pipeline changes into normal software changes with history and rollback.

Where do Azure Data Lake Gen2 and Synapse data warehouse fit?

A data factory moves data, but it needs somewhere to put it. Two places show up in almost every Azure build.

Azure Data Lake Gen2 is low-cost storage for everything in its raw and cleaned form. You land source data here first, keep the history, and reprocess it later if a rule changes. It stores files, not tables, so it's the staging area before anything is query-ready.

A Synapse data warehouse is where the modeled, report-ready tables live. It's built for the kind of fast aggregation a dashboard needs across millions of rows. The pipeline carries data from the lake into the warehouse on schedule. Storage keeps the data, the warehouse serves it, and the pipeline moves data between them.

Data factory vs the other options

"Data factory" now names a few different products. They share an engine but suit different setups. Here's how they line up.

Azure Data Factory (ADF)Standalone cloud pipeline serviceCopying and transforming data across many sourcesPipeline runs and data movement

If you're starting fresh on Azure, standalone ADF or Fabric Data Factory are the two live choices. Synapse Pipelines make sense when the warehouse is already there. SSIS is the one you migrate away from, not toward.

How much does a data factory cost to run?

ADF bills by activity, not by a flat monthly fee. You pay a small amount per pipeline run, a bit more per Copy activity based on how much data moves, and separately for Mapping Data Flow compute by the hour it runs.

For a normal setup, a few nightly pipelines moving reasonable volumes, the bill lands in the tens of dollars a month, not the thousands. The Data Flow compute is usually the biggest line, so switching heavy transforms to run less often, or in the warehouse itself, is the first place to trim. Keeping full history in Azure Data Lake Gen2 costs so little that it rarely moves the number much.

The real cost of skipping a data factory isn't the Azure bill. It's the analyst hours spent rebuilding the same export every week, and the meetings where two teams argue over which spreadsheet is right.

Frequently asked questions

Is a data factory the same as Azure Data Factory? In practice, yes. When people say data factory they almost always mean ADF, the specific Microsoft service. Fabric now has its own Data Factory too, which is the same idea inside the Fabric product.

Do I still need a Synapse data warehouse if I have a data factory? Usually yes. A data factory moves and shapes data, but reports run faster against a Synapse data warehouse built for aggregation. The pipeline feeds the Synapse data warehouse; it doesn't replace it.

Does a data factory replace SSIS? For most cloud work, yes. ADF covers what SSIS did on-premises, and it can even run existing SSIS packages during a migration so you move over gradually rather than rewriting everything at once.

Is Fabric Data Factory different from Azure Data Factory ADF? They share the same pipeline engine and most concepts carry over. Fabric Data Factory sits inside Microsoft Fabric and writes to OneLake, and it's billed through Fabric capacity rather than per activity. If your team is standardizing on Fabric, that's the version to learn.

How long does it take to build a first pipeline? A simple copy-and-schedule pipeline is a half-day of work once your connections are set up. A full nightly load with cleaning, incremental logic, and a warehouse target is more like one to two weeks for a first proper build.
